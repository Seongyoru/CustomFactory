## 1. 애니메이션 연동 4가지 다시 적용

### 요청
> DigitalTwinDashboard.jsx에 애니메이션 연동 4가지 다시 적용

### 배경
이전 세션에서 인코딩 사고로 `DigitalTwinDashboard.jsx`가 손상됐고, 백업으로 복원하는 과정에서
백업 시점 이후의 변경분 4가지가 유실된 상태였습니다. 이전 세션 기록에서 그 4가지를 특정한 뒤 다시 적용했습니다.

### 대응
| 항목 | 내용 |
|---|---|
| 애니메이션 배속 연동 | `taktSec = 표준시간 ÷ 수량`을 구하고, GLB `TOTAL` 클립 1회(7.2초)가 택트타임만큼 걸리도록 재생 속도를 맞춤 |
| 공정 시퀀스 HUD | 좌하단에 `PROCESS_PHASES` 6단계 간트 + 재생 헤드 |
| 배속 단계 변경 | `SPEED_STEPS = [0.25, 0.5, 0.75, 1, 2, 3, 4]` 인덱스 슬라이더 |
| E-STOP 시 정지 | `animPaused` 전달 |

계산식:

```
animTimeScale = PROCESS_CYCLE_SEC / taktSec × (시뮬레이션 배속)
```

엑셀 업로드로 택트가 극단적인 작업이 들어와도 화면에서 볼 수 있도록 비율을 `0.1 ~ 4`로 제한했습니다.

### 곁들인 것
공정 시각이 4Hz로 올라오는데 이를 루트 state로 두면 초당 4번 대시보드 전체가 리렌더됩니다.
상태를 뷰포트 안으로 내리고 3D 씬을 `React.memo`로 감쌌으며, memo가 실제로 걸리도록
`theme`은 `useMemo`, `handleMove`는 `useCallback`으로 참조를 고정했습니다.

### 검증
현재 작업(900초 ÷ 120EA = 7.5 s/EA) 기준 `×0.96` 산출을 브라우저 DOM에서 실측.

## 2. 재생 배속을 정수로 표현

### 요청
> 배속이 0.96 배속 말고 정확한 정수로 표현해주는게 좋아보여

### 확인한 것
표시만 다듬을지, 재생 속도 자체를 스냅할지에 따라 동작이 달라져 세 가지 선택지를 제시했고
**"표시만 반올림"** 을 선택받았습니다.

### 대응
단순 `Math.round`를 쓰면 0.25배속에서 내부값 0.24가 **`×0`** 으로 표시되는 문제가 있어,
가장 가까운 배속 단계로 반올림하는 `fmtAnimScale`을 만들었습니다.

| 배속 | 내부값 | 표시 |
|---|---|---|
| 0.25x | 0.24 | ×0.25 |
| 0.5x | 0.48 | ×0.5 |
| 0.75x | 0.72 | ×0.75 |
| 1x | 0.96 | **×1** |
| 2x | 1.92 | **×2** |
| 3x | 2.88 | **×3** |
| 4x | 3.84 | **×4** |

### 검증
7단계 전부 실측. 택트 연동이 살아 있는지도 작업을 바꿔가며 확인:
`7.5 s/EA → ×1`, `9.0 s/EA → ×0.75`, `6.3 s/EA → ×1`.

### 남겨둔 트레이드오프
표시와 실제 속도가 미세하게 어긋납니다. 1배속에서 화면은 `×1`이라고 하지만 실제로는 0.96배로
돌아갑니다(4% 차이, 육안 구분 불가). 정확히 일치시키려면 재생 속도 자체를 스냅해야 합니다.

## 3. 대기열 취소 · 진행률 점검 · 소요 시간 · 탭 제목

### 요청
> 1. 작업 대기열의 취소 버튼이 작동하는 역할이 없는 것 같아 (…) 취소할건지 물어보는 작은 팝업도 있어야겠지
> 2. 생산라인 진행률 (…) 개포장만 적용되는 것 같고 이송 충전 검사는 작업을 추가해도 변동이 없어보이는데 확인 부탁해
> 3. (추가) 시뮬레이션 제어에서 (…) 몇시간 몇분 걸린다고 보여주는게 좋아보여
> 4. (추가) 윈도우 탭 이름을 EGIS Factory로

### 3-1. 작업 취소
취소 버튼에 `onClick`이 아예 없었습니다. **선택 → 확인 팝업 → 제거** 흐름을 넣었습니다.

- 작업을 클릭하면 선택(포인트 컬러 테두리), 다시 누르면 해제
- 선택 전에는 버튼 비활성 + 안내 문구
- 팝업에 작업명·수량·표준시간·상태 표시, **진행 중인 선두 작업이면 "현재 공정이 즉시 중단된다"** 경고 추가

행 우측 휴지통도 같은 팝업을 거치게 바꿨습니다(한쪽만 즉시 삭제되면 위험).

### 3-2. 생산 라인 진행률 — 지적이 맞았습니다
`이송 78 / 충전 54 / 검사 31`이 **하드코딩된 상수**였습니다. 무엇을 해도 움직이지 않습니다.

대기열에서 계산하도록 바꿨습니다. 작업명으로 4단계에 배정하고
(`충전 후 계량/검사`처럼 겹치는 이름은 좁은 규칙인 **검사**를 먼저 판정),
**분모는 그 단계 작업들의 표준시간 합, 분자는 라인 경과시간**입니다.

4단계는 순차가 아니라 동시에 도는 공정이라(3D에서도 컨베이어·절단·카트·충전이 한 사이클에 함께 움직임)
같은 라인 시계를 네 단계에 모두 적용했습니다.

> 첫 구현에서는 선두 작업의 단계만 움직이고 나머지는 0%로 고정돼, 여전히 "안 움직이는" 문제가
> 남았습니다. 지적하신 증상이 그대로 재현돼 위 방식으로 다시 고쳤습니다.

**검증** — 검사 작업 1건 추가 시:

| | 추가 전 | 추가 후 |
|---|---|---|
| 검사 | 1건 · 08:00 · **100%** | 2건 · 16:00 · **56%** |

4배속 6초 관찰에서 개포장 57→58%, 이송 39→40%, 충전 34→35%로 모두 진행.
작업이 없는 단계는 `—`로 비웁니다.

**알려진 특성** — 배정 물량이 적은 단계는 경과시간이 물량을 넘어서면 100%에 붙어 멈춥니다.
현재 작업이 한 바퀴 돌면 리셋됩니다.

### 3-3. 예상 소요 시간
기존 완료 시각은 두고 **예상 소요 시간**을 위에 추가, 근거(`Cycle 42.7s × 100회`)도 함께 표시.

절단기 기준 실측: 1회 `43초`, 5회 `3분`, 90회 `1시간 4분`, 100회 `1시간 11분`, 1000회 `11시간 51분`.

### 3-4. 탭 제목
`TWINOPS · Smart Factory Digital Twin` → `EGIS Factory · Digital Twin System`

## 4. 2호기 복제

### 요청
> z축으로 10정도 떨어진 위치에 라인2번을 라인 1과 똑같이 배치 (…) 라인 1번이 활성화 되어있을땐 라인2번은 불투명도 적용 (…) 라인 3번까지는 없어도 될 것 같아

### 대응
`factoryAssets.js`에 `PRODUCTION_LINES`를 추가했습니다. 설비를 다시 정의하지 않고
**원점만 갖는 목록**이라, 라인을 늘릴 때 한 줄만 추가하면 같은 구성이 복제됩니다.

- **활성 라인** — 클릭 선택, 기즈모, 상태 링, 라벨 모두 동작
- **비활성 라인** — 전부 `StaticModel`, 불투명도 `0.16`. 핸들러가 없어 **레이캐스트 대상에서 자동 제외**되므로 뒤쪽 고스트가 클릭을 가로채지 않음

건물 셸(INTERIOR)은 Z ±26.2m라 2호기도 같은 건물 안에 들어옵니다. **셸은 복제하지 않고 하나만** 뒀습니다.
라인 3은 요청대로 제외했습니다.

고스트일 때는 알파맵 보정을 건너뜁니다 — 알파맵이 `transparent`/`alphaTest`를 다시 건드려
카트 유리가 얼룩지기 때문입니다.

### 곁들인 것 — 카메라
요청에 없었지만, 라인을 바꿔도 카메라가 남아 있으면 "2호기를 골랐는데 눈앞 라인만 흐려지는" 상태가 됩니다.
두 라인 원점의 **차이만큼만 카메라와 타깃을 평행이동**하도록 했습니다. 각도·줌은 유지됩니다.

## 5. 위치 변경과 피벗 어긋남

### 요청
> 2호기 위치가 z +10 말고 -10으로 (…) 피벗 위치가 10만큼 이동한것 같은데 해결가능할까?

### 원인 — drei 구현을 열어 확인
`node_modules/@react-three/drei/core/TransformControls.js`:

```js
React.createElement("primitive", { object: controls, ... }),
React.createElement("group", { ref: group }, children)
```

기즈모를 **자기가 놓인 부모 그룹의 자식으로** 그리는데, 컨트롤 자신은 대상 객체의
**월드 좌표**로 위치를 잡습니다. 라인을 `<group position={line.origin}>`으로 감쌌기 때문에
원점이 한 번 더 곱해져 기즈모만 정확히 라인 간격(10m)만큼 밀렸습니다.

### 대응
래퍼 그룹을 없애고 **라인 원점을 각 설비 좌표에 미리 더하는** 방식으로 바꿔 이중 적용을 제거했습니다.
저장 값이 오염되지 않도록, 기즈모가 돌려주는 월드 좌표에서 원점을 다시 뺍니다:

```js
onMove(id, [+(x - ox).toFixed(2), +(y - oy).toFixed(2), +(z - oz).toFixed(2)])
```

## 6. 라인별 완전 분리

### 요청
> 라인별로 따로 놀아야 해, 그리고 라인별로 생산라인 진행률이 독립적으로 적용되게 (…) 1라인에서 작업 대기열 수정해도 2라인도 같이 적용된 것 처럼 보여서

### 대응
| 대상 | 변경 |
|---|---|
| 설비 배치 | `offsets` → `offsetsByLine` |
| 작업 대기열 | `jobs` → `jobsByLine` |
| 경과시간 | `useJobTimer` → `useLineJobTimers` (라인마다 독립적으로 진행) |
| 지시번호 | 1호기 `001~`, 2호기 `101~` |

보고 있지 않은 라인도 계속 진행해서, 라인을 오가도 시간이 멈추거나 리셋되지 않습니다.
작업 카탈로그(`templates`)만 라인 공용입니다.

### 검증
2호기에서 선두 작업을 취소하고 검사 작업을 추가한 뒤:

| | 개포장 | 이송 | 충전 | 검사 |
|---|---|---|---|---|
| **2호기** (수정함) | — | 2건 36% | 1건 31% | **2건 49%** |
| **1호기** (안 건드림) | 1건 52% | 2건 36% | 1건 31% | **1건 98%** |

1호기는 그대로고, 2호기로 돌아가면 수정 상태가 유지됩니다.

### 남겨둔 것
**설비 상세 패널(시리얼·점검 이력·소모품·메모)은 아직 라인 공용입니다.**
`FACTORY_ASSETS`가 라인 구분 없는 설비 마스터라, 2호기 절단기도 1호기와 같은 값을 보여줍니다.
라인별 설비 마스터가 필요하면 데이터 구조를 새로 짜야 합니다.
→ **2026-08-26 해소** — 아래 "라인별 설비 마스터" 절 참조 (`src/data/lineAssets.js`).

## 7. 설비 오류 알람

### 요청
> 1. 붉은 색 led 비네팅 깜빡이게 하고 (…) 팝업 창이 하나 떠야 해
> 2. 무슨 생산라인, 무슨설비에서, 언제, 어떤오류인지 (…) 해당 설비로 이동 버튼
> 3. 이동 버튼을 눌러야 비네팅이 사라지고 (…) 줌인이 되며 해당 설비는 빨갛게 (…) 작업중이 아닌 상태를 보여줘야겠지
> 4. 운전모드 왼쪽쯤에 오류 상황 테스트 버튼

### 7-1. 비네팅
화면 가장자리만 붉게 물들이고 **중앙 42%까지는 완전 투명**이라 판독을 방해하지 않습니다.
`prefers-reduced-motion` 사용자에게는 깜빡임 대신 고정 표시로 나갑니다.

### 7-2. 팝업
```
EQUIPMENT FAULT
벨트 슬립 감지                    알람 코드 E-1123

생산 라인   DM뷰 - Line_2
발생 설비   Conveyor Unit (원자재 이송 컨베이어)
설비 위치   절단된 HPG 원자재 이송
발생 시각   2026-07-31 14:24:33

오류 내용   구동 엔코더와 종동 엔코더의 회전차가 3초 이상
            허용치를 초과했습니다…

            [ 해당 설비로 이동 ]
```

**닫기 버튼도, 바깥 클릭으로 닫기도 없습니다.** 놓치면 안 되는 알림이라 이동 버튼을 눌러야만 사라집니다.

설비별 오류 시나리오 6종을 `FAULT_SCENARIOS`에 정의했고, 코드 대역도 계열별로 나눴습니다
(절단 2000, 이송 1000, 로봇 3000/5000, 승강 4000, 카트 6000).
**실제 OPC-UA 연동 시 같은 형태(`{ assetId, code, title, detail }`)로 알람을 넣기만 하면** 그대로 동작합니다.

### 7-3. 이동 버튼 — 실측 결과

| | 결과 |
|---|---|
| 비네팅 | 즉시 정지 |
| 팝업 | 닫힘 |
| 라인 | L1 → **L2 자동 전환** |
| 설비 선택 | 상세 패널 열림 |
| 설비 상태 | `작업 중 / 정상 이송 중` → **`오류 / [E-1123] 벨트 슬립 감지`** |

## 검증에 대해

매 변경마다 프로덕션 빌드를 돌리고, 브라우저에서 DOM을 직접 읽어 값을 확인했습니다.
이전 세션의 인코딩 사고를 감안해 **한글 문자 수와 U+FFFD 개수**도 매번 확인했습니다(깨짐 0 유지).

### 확인하지 못한 것

**3D 화면 표현은 전 구간에서 검증하지 못했습니다.** 브라우저 미리보기 창이 표시되지 않아
`document.hidden = true` 상태이고, `requestAnimationFrame`이 **1.5초 동안 0프레임**입니다.
react-three-fiber는 렌더 루프가 rAF에 묶여 있어 씬이 아예 마운트되지 않습니다
(`window.__mixers` 0개). GLB 10개는 모두 200으로 내려받아지므로 로딩 문제는 아닙니다.

직접 눈으로 확인이 필요한 항목:

- 2호기가 Z−10에 그려지는지, 고스트 불투명도 `0.16`이 적절한지
- 오류 설비의 붉은 발광 세기(`0.3 ~ 1.0`)와 줌인 거리·각도
- 한 라인만 비상 정지했을 때 다른 라인 설비가 계속 움직이는지
- 3D 바닥 상태 링이 정지 시 적색으로 바뀌는지

2D 지표(경과시간·진행률·HUD·푸터·상세 패널)는 모두 실제 클릭과 DOM 판독으로 확인했습니다.
