## 1. 코드 구조 개편

`DigitalTwinDashboard.jsx` 한 파일에 있던 2D UI 전체를 파일 헤더에 적혀 있던
분리 가이드대로 쪼갰다. **동작 변경 없이 이동만** 한 뒤 실측으로 확인하고 다음 단계로 넘어갔다.

## 2. 데이터 영속화 — `lib/persist.js`

- 키 네임스페이스 `egis-dt.v1.*`. 스키마가 바뀌면 버전을 올려 구버전과 충돌 없이 초기화.
- `usePersistentState(key, initial, revive)` — useState 와 같게 쓰고 자동 저장.
  메모의 작성 시각처럼 Date 복원이 필요하면 `revive` 로 되살린다.
- 저장 대상: 대기열/카탈로그/배치/메모/경과시간/누적통계/생산실적/이벤트/테마/세션.
  **비상 정지 상태와 알람은 저장하지 않는다** — 재기동 시 안전 기본값으로 시작.
- 데모 초기화: 리포트 센터 좌하단 "데모 데이터 초기화" (관리자 전용, 2단계 확인).
- 실서버 연동 시 이 파일만 REST/WebSocket 저장소로 교체하면 된다.

## 3. 생산 엔진 — `hooks/useProductionEngine.js`

기존 타이머는 선두 작업 경과시간을 `% 표준시간` 으로 **순환만** 시켰다. 이제:

- 경과시간이 표준시간에 도달하면 **작업이 완료**되고 대기열이 전진한다 (다음 작업이 RUNNING).
- 완료 실적이 `production` 에 기록된다 — 수량·불량(0~2% 시뮬레이션)·계획/실적 시간.
- 사이클 편차(공칭 -6%~+2%)를 줘서 계획 대비 실적이 96~100% 부근에서 살아 움직인다.
- 라인별 누적 통계(가동·정지·생산·불량)를 쌓는다 → OEE 근거.
- 대기열이 비면 라인은 유휴 — 3D 애니메이션도 함께 멈춘다.
- 작업 추가 시 표준시간은 기본 수량 대비 **비례 환산**한다 (240EA 추가 시 120EA 표준시간의 2배).

### 잡은 버그 — StrictMode 이중 완료
틱 로직(통계 누적·완료 콜백)을 `setState` 업데이터 안에 뒀더니 React StrictMode 가
업데이터를 두 번 호출해 **같은 작업이 2번 완료**됐다. 틱 계산을 ref 미러로 빼고
state 는 결과만 받게 고쳤다. 같은 이유로 이벤트/실적 레코드 생성도 업데이터 밖으로 옮겼다.

## 4. 실시간 텔레메트리 — `telemetry/` + `hooks/useTelemetry.js`

- **소스 인터페이스**: `{ info, subscribe(listener), start(), stop() }`,
  방출 형태 `{ at, readings: {라인: {설비: {temp, vib, amp}}}, latencyMs }`.
  실제 OPC-UA/MQTT 게이트웨이 어댑터를 같은 형태로 만들어 갈아끼우면 화면은 그대로 동작한다.
- 시뮬레이션 구현: OU 랜덤워크로 설비별 기준값 주변을 배회. 앱 상태에 반응 —
  정지/유휴 라인은 주변온도로 식고, **오류 설비는 진동 ×3 · 전류 ×1.6 · 온도 +18°C** 로 치솟는다.
- UI: 설비 상세에 "실시간 센서" 패널(최근 2분 스파크라인, 정상/주의/위험 판정),
  하단 바의 "OPC-UA 연결됨/Latency 24ms" 하드코딩을 실제 소스 상태 표시로 교체.

검증: 오류 발생 → 컨베이어 진동 2.15 → 6.5 mm/s (기준 2.1 의 ×3 수렴), 해제 → 2.5 복귀 실측.

## 5. 리포트 센터 — GNB "리포트"

- **생산 리포트**: 금일 KPI 5종 / 라인별 OEE(가동률·성능·품질) / 시간대별 생산량 차트 / 완료 작업 테이블
- **알람 이력**: 알람 발생·확인·해제, 비상 정지 on/off
- **작업 로그**(감사): 모든 조작 이력 — **누가** 했는지 기록 (`ESTOP_ON: 게스트` 식)
- **엑셀 내보내기**: 생산 실적 / 라인 요약(OEE) / 알람 이력 / 이벤트 로그 4개 시트

OEE 산식: A=가동/(가동+정지), P=Σ계획/Σ실적 (완료 작업), Q=(생산-불량)/생산.

## 6. 로그인/권한 — `auth/`

| 계정 | 역할 | PIN | 가능한 것 |
|---|---|---|---|
| 백성열 | 시스템 관리자 | 0000 | 전부 + 설비 배치 조정 + 데이터 초기화 |
| 김현수 | 라인 운영자 | 1111 | 작업 관리 · E-STOP 해제 · 메모 · 오류 테스트 · 내보내기 |
| 게스트 | 모니터링 전용 | 2222 | 조회 + **E-STOP 작동만** |

- **E-STOP '작동'은 누구나, '해제'는 운영자 이상** — 비상 정지는 막는 쪽이 위험하다.
- 배치 기즈모는 관리자 외에는 아예 뜨지 않는다 (씬이 `onMove` 없음을 인지).
- 데모용 로컬 인증이다. 상용 배포 시 `auth.js` 의 USERS 만 서버 인증으로 교체하면
  화면의 권한 게이트(`hasPermission`)는 그대로 동작한다.

## 7. 성능

- **GLB Draco 압축**: 43.9MB → 18.4MB (58%↓). 원본은 git 이력에 있다
  (`git show 65c05fc:public/models/….glb`). 디코더는 CDN 이 아니라 `public/draco/` 에
  번들 — **폐쇄망(공장 내부망)에서도 동작**한다.
  - INTERIOR(8.5MB)는 4096² CMYK 계열 JPEG 텍스처가 sharp 에서 변환 실패해 텍스처는 원본 유지.
    추후 텍스처를 sRGB 2048² 로 재출력하면 ~3MB 대까지 가능.
- **xlsx 지연 로딩**: 엑셀 기능을 실제로 쓸 때만 내려받는다. 메인 번들 1,716KB → 1,329KB.

## 검증에 대해

이전 세션과 같은 제약으로 **브라우저 미리보기 창이 표시되지 않아 3D 화면 표현은
직접 확인하지 못했다** (rAF 미작동 → 씬 미마운트). GLB 10개의 다운로드·Draco 파싱은
네트워크/콘솔 실측으로 확인했고(에러 0), 2D 전 기능은 DOM 클릭·판독으로 실측했다:

- 로그인 3계정 × 권한 차단/허용 매트릭스
- 작업 완료 → 대기열 전진 → 실적 1건 기록 (이중 기록 버그 수정 후 재검증)
- 새로고침 후 세션·대기열·경과시간 유지
- 오류 알람 → 센서 급등 → 해제 → 회복
- 리포트 3탭 · KPI · OEE 값 · 초기화 2단계 확인

### 직접 눈으로 확인이 필요한 것
- Draco 압축 후 3D 외관 (지오메트리 양자화로 인한 미세 차이 가능성 — 이상 시
  `git checkout 65c05fc -- public/models` 로 원복)
- 카트 유리 알파맵(`10 - Default` 머티리얼 런타임 보정)이 압축 후에도 올바른지
- 대기열이 빈 라인의 3D 정지 연출
